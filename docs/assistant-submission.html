Sentinel: conversational security lab

Sentinel extends the existing IoT botnet detection website with natural-language website controls, a synthetic security monitor, and a cybersecurity tutor grounded in all 14 supplied course briefs, plus the existing project materials. It supports typed commands, optional browser speech recognition and spoken replies. Users can change appearance, play or pause a phishing-training video, navigate to learning and monitoring sections, filter logs, and simulate a security incident.

Website URL

https://manganjokean.github.io/computer-security-project/#security-studio

Implementation summary

The implementation uses HTML, responsive CSS and JavaScript ES modules, hosted in the repository’s existing GitHub Pages docs folder. WebLLM 0.2.79 loads Qwen2.5-0.5B-Instruct-q4f16_1-MLC in the browser through WebGPU after the user selects “Enable browser AI.” A small model and recent conversation history support follow-up explanations. Relevant curated notes from the supplied course briefs and existing project ground assignment and project questions. Verified study notes appear alongside generated explanations. Generation uses repetition penalties to reduce repeated text, but this small model can still produce weak or inaccurate answers. Source links are supplied by the application, rather than invented by the model.

A deterministic intent parser and action allowlist control the website independently of model inference. Model-generated text is rendered with textContent and never evaluated as code. Study mode offers curated answers and contextual follow-ups without downloading the model. It is explicitly labeled as non-generative. No API key, paid service or backend is required.

The monitor computes login totals, failures, unique flagged IPs, synthetic attack count and a simple threat level from in-memory events. Three failures from one address within five minutes flag that IP. A synthetic flood sets the threat level to High. All sample IPs use documentation ranges. These rules illustrate investigation and do not run the repository’s trained classifiers.

Demonstration video script

Record your screen while completing this sequence. The phishing-training MP4 is a website feature, not the required recording of your own demonstration.

  1. Open Sentinel and explain that the monitoring events are synthetic.
  2. Select “Enable browser AI.” Wait for “Browser AI ready” before demonstrating generated answers. This initial setup downloads the model.
  3. Type or speak: “Change the background to dark blue.” Show the visible change.
  4. Type or speak: “Play the cybersecurity training video.” Show playback, then say “Pause the video.”
  5. Type or speak: “Open the learning section.” This demonstrates a third interactive feature.
  6. Ask “What is phishing?”, “How does MFA work?” and “What is the difference between DoS and DDoS?” Ask a follow-up such as “Explain that more simply.”
  7. Ask “What is Assignment 6 about?” and “How does that relate to the IoT project?” to connect the IDS assignment with the actual project.
  8. Say “Simulate an attack” and “Show suspicious events”; explain normal versus suspicious behavior.
  9. Say “Restore the original appearance.” During the demonstration, trigger website actions through the conversation, rather than the page’s action buttons.

Challenges and improvements

GitHub Pages provides static hosting, so a backend API secret cannot safely live in the site. Browser inference avoids exposed credentials but needs a compatible WebGPU browser, memory and an initial model download. The small model can make mistakes, so project notes and references accompany answers. Future improvements include a larger grounded model, more flexible intent classification, richer authorized log ingestion, incident correlation and broader accessibility testing.

The assistant covers all 14 supplied course briefs from Assignments 1–9.2, with aliases matching filename/header differences, plus the IoT project, XSS research and Labs 1–2. It distinguishes the uploaded IDS Assignment 6 from the existing XSS page’s label. Study summaries explain requirements and concepts; they are not evidence that student solutions or experiments are complete. Browse the course guide. Voice and device-specific speech permissions require testing on your own browser. Do not enter credentials or personal information. Speech recognition may use the browser vendor’s online service; text chat itself is processed locally.
