TECH 3498 / ASSIGNMENT 1

Security foundations

Assignment 1 asks about computer security, passive and active threats, network attack categories, and ATM security requirements. Computer security protects systems and information against unauthorized disclosure, alteration and disruption. Confidentiality protects secrets; integrity protects correctness; availability keeps authorized services usable. Passive attacks observe information (message disclosure and traffic analysis). Active attacks change or disrupt behavior (masquerade, replay, message modification and denial of service). For an ATM, protect the PIN and account data (high confidentiality), prevent unauthorized balance changes and withdrawals (critical integrity), and keep legitimate withdrawals available (high availability). Importance depends on the service’s risk assessment.

Project connection: botnet floods threaten availability, altered logs undermine integrity, and exposed account data threatens confidentiality. A detector can observe suspicious traffic without proving who caused it.

TECH 3498 / ASSIGNMENT 2

Cryptography and authentication

Assignment 2 covers symmetric ciphers, authentication, public-key systems, signatures, certificates, key distribution, and two challenges. A symmetric cipher has plaintext, encryption algorithm, shared secret key, ciphertext and decryption algorithm. Classical authentication approaches use encryption in an appropriate authenticated protocol, a MAC, or a hash combined with authenticated keying/signing; a bare unkeyed hash does not authenticate a sender. Public-key systems use paired public/private keys, algorithms, plaintext and ciphertext for encryption, signatures and key establishment. A signature supports integrity and public verification of the signer; a MAC uses a shared secret and cannot distinguish which key holder created it. A certificate binds an identity to a public key through an issuer’s signature. Authenticate the recipient’s public key before protecting a random session key with a secure standardized scheme.

Challenge: if the transmitted values are r XOR k and then r, an observer computes k by XORing those values. Neither a signature nor a MAC alone prevents replay: bind a nonce, counter or timestamp to the authenticated message and reject repeats. Both detect altered authenticated messages. A shared-key MAC cannot settle a dispute between Alice and Bob because either can generate it; signatures provide stronger attribution subject to trusted key binding and key custody. Project connection: protect log integrity and authenticate monitoring messages.

TECH 3498 / ASSIGNMENT 3.1

Passwords and biometrics

The file labeled 3.1 is headed Assignment 3 and covers password secrecy, biometrics, error thresholds and password-search calculations. Password threats include guessing, reuse, phishing, keylogging, shoulder surfing and offline cracking of stolen hashes. Biometrics can use fingerprints, face, iris, retina and hand geometry. Enrollment records a reference template; verification is a one-to-one claimed-identity check; identification searches one-to-many. False match rate measures incorrect matches; false nonmatch rate measures rejected genuine samples. A stricter match threshold generally reduces false matches while increasing false nonmatches. Protect templates and use MFA rather than treating biometrics as revocable passwords.

For four uniformly random letters, the space is 26^4 = 456,976; nonrepeating exhaustive guessing averages (456,976 + 1)/2 = 228,488.5 seconds, about 2.64 days at one guess/second. Per-character feedback leaks a prefix: with sequential distinct guesses and one second per character test, four positions average 4 × 13.5 = 54 seconds; timing depends on the stated feedback model. For ten uniformly random printable ASCII characters, exhaustive time is 95^10 / 6,400,000 ≈ 9.36e12 seconds, about 296,000 years; average discovery is half. These idealized spaces do not describe human-chosen passwords. Project connection: failed-login bursts need rate limits and MFA, not merely alerts.

TECH 3498 / ASSIGNMENT 3.2

Access control

Assignment 3.2 asks about DAC versus MAC, subject classes, access rights, ACLs, capabilities and protection domains. Discretionary access control (DAC) lets authorized owners delegate permissions. Mandatory access control (MAC here means mandatory access control, not message authentication code) enforces centrally administered labels and policy. In the traditional owner/group/world model, a subject is the owner, a member of an authorized group, or another user; confirm your textbook’s class terminology. An access right permits an operation such as read, write or execute. An ACL lists permitted subjects and operations for an object; a capability is an unforgeable authority held by a subject for an object. A protection domain is the set of objects and rights available to a subject or execution context.

Project connection: the assistant uses a small action allowlist and least privilege. It can change page appearance and inspect synthetic events, but cannot acquire arbitrary file or operating-system permissions. An object-centered ACL and a subject-held capability represent authority in different ways.

TECH 3498 / ASSIGNMENT 4.1

Database security

Assignment 4.1 covers SQL injection, cascading authorization, database-encryption tradeoffs, a name-search query, a login-query fragment and a grant-dependency diagram. SQL injection occurs when input changes query structure; use prepared statements and least-privilege accounts. Cascading authorization lets a grantee delegate privileges with grant option; cascading revocation can remove dependent grants when their valid authorization path disappears. Encryption adds key-management, performance, indexing/search and recovery complexity; encryption at rest does not prevent an authorized application from issuing an injected query. In the author example, SELECT retrieves id, forename and surname for John Smith. An unescaped apostrophe in a name can break concatenated SQL. Stacked destructive statements only execute if driver/database settings and privileges permit them; do not assume the payload always succeeds.

The login figure concatenates login, password and a numeric PIN into a SELECT accounts FROM users query. Ordinary sample inputs produce conditions login = doe, pass = secret and pin = 123 (string values must be quoted). A tautology and comment can bypass intended checks in unsafe concatenation, depending on SQL dialect and parsing. Use a parameterized query rather than testing attacks on a live database. The grant diagram shows A→B at 10, B→C at 20, C→D at 30, A→C at 40, D→E at 50 and C→D at 60; revoking B→C at 70 requires tracking alternate authorization and grant-time dependencies under the specified DBMS policy. Project connection: keep untrusted log or chat data separate from executable instructions.

TECH 3498 / ASSIGNMENT 4.2

Buffer overflows

Assignment 4.2 defines buffer overflows, their target locations, consequences, required conditions and stack-overflow behavior. An overflow writes beyond a buffer’s allocated bounds. Typical target areas are stack, heap and static/global storage. Consequences include corrupted data, crashes, information exposure and sometimes control-flow hijacking. A conceptual attack requires finding an unsafe input path and understanding what adjacent data or control state can be overwritten. In a stack overflow, oversized input can corrupt nearby stack data and potentially saved control information. This is a conceptual explanation, not a device-specific exploit.

Defenses include memory-safe languages, bounds checking, compiler hardening, stack canaries, ASLR, non-executable memory and least privilege. No single mitigation guarantees safety. Project connection: validate log lengths and avoid memory-unsafe parsing; the website bounds chat input and never evaluates generated code.

TECH 3498 / ASSIGNMENT 4.3

Defensive programming

Assignment 4.3 compares quality/reliability with security and asks about defensive programming, input sources and unvalidated data passed between users. Quality concerns fitness and correctness; reliability concerns consistent operation under expected conditions; security also addresses intentional misuse and adversarial input. Defensive programming treats external assumptions as untrusted and checks type, length, range, format and business rules with allowlists where appropriate. Inputs include forms, files, URLs, network messages, environment variables, databases, APIs and interprocess messages. Passing untrusted input to another user can cause XSS, injection, spoofing, malicious links or information disclosure.

Validation alone is not sufficient: use context-aware output encoding, parameterized queries and safe DOM APIs. Project connection: chat messages and model responses are inserted as text, so text resembling an HTML script is displayed rather than executed. The language model cannot introduce new website actions.

TECH 3498 / ASSIGNMENT 5.1

Malware

Assignment 5.1 asks about malware propagation, executable versus macro viruses, worm access, countermeasures and four traditional antivirus generations. Broad spread mechanisms include infecting existing executable/content, exploiting remote vulnerabilities and deceiving users into installing or opening malicious content. Executable viruses infect machine-code programs; macro viruses use document/application scripting. Worms can spread through vulnerable network services, stolen or weak credentials, shared resources and messaging, without attaching themselves to a host program in the virus sense. Countermeasures include prevention, detection, containment, eradication, recovery and tested backups.

A common historical four-generation taxonomy is simple signature scanners; heuristic scanners; activity traps/behavior monitoring; and full-featured integrated protection. These labels describe textbook history rather than a complete modern product taxonomy. Project connection: Mirai/BASHLITE-infected IoT devices generate observable malicious traffic, motivating network-side detection plus device patching and credential hygiene.

TECH 3498 / ASSIGNMENT 5.2

Denial of service

Assignment 5.2 asks for DoS, targeted resources, flooding goals, DDoS and defenses. DoS reduces legitimate access by exhausting resources or exploiting a failure. Targets include network bandwidth, connection/state tables, CPU, memory, storage and application worker capacity. Flooding overwhelms capacity with traffic or requests. DDoS coordinates many sources, often compromised devices. Filtering and rate limiting at network boundaries help; volumetric traffic often needs upstream ISP or mitigation-provider filtering before the organization’s link is saturated. Patch implementation flaws, constrain expensive requests and plan incident response.

Project connection: Mirai is an IoT botnet associated with distributed floods. The synthetic SYN alert illustrates an investigation event; it does not transmit traffic or certify an attack. An IDS flags behavior, while filtering and upstream capacity management are prevention/mitigation controls.

TECH 3498 / ASSIGNMENT 6

Intruders and intrusion detection

The supplied Assignment 6 is about intruders and intrusion detection: intruder classes, attack methodology, IDS components, false positives/negatives, detection approaches and public-information exposure. A common four-category motivation taxonomy is cybercriminals, activists, state-sponsored actors and other intruders (including opportunists/insiders); confirm the course textbook’s exact labels. A defensive model of the intrusion lifecycle includes reconnaissance, access attempts, privilege escalation, persistence, activity and concealment. The three logical IDS components are sensors/data collection, an analyzer/detection engine and a user interface/reporting component. A false positive flags benign activity; a false negative misses an actual attack. Anomaly detection compares behavior with a baseline; signatures match known patterns, while heuristics use rules about suspicious characteristics.

The challenge asks how public technical, staff and organizational information can aid reconnaissance while public disclosure also serves business and legal needs. Publish what is necessary, minimize unnecessary technical detail, review exposure and train staff without obstructing required transparency. Project connection: the IoT classifiers and synthetic monitor illustrate detection and false-positive tradeoffs. TECH 3498 / ASSIGNMENT 7

Firewalls

Assignment 7 covers firewall design goals, access-control characteristics, packet-filter weaknesses and internal versus external firewalls. Three classic goals are: all traffic crossing the protected boundary passes through the firewall; only policy-authorized traffic passes; and the firewall itself resists compromise. Four traditional controls are service control (which services), direction control (inbound/outbound), user control (which users) and behavior control (how services are used). Basic packet filters examine headers and may lack application/user context, be vulnerable to spoofing or rule mistakes, and miss attacks in permitted or encrypted traffic. They cannot stop traffic that bypasses them.

An external firewall enforces the perimeter between trust zones such as the internet and the organization. Internal firewalls segment systems and limit lateral movement. Project connection: place IoT devices in a restricted segment and correlate firewall logs with IDS alerts. A firewall enforces allowed traffic; an IDS analyzes suspicious activity. Both require monitoring and correct policy.

TECH 3498 / ASSIGNMENT 8

System hardening and virtualization

Assignment 8 asks about securing systems, automated patching, virtualization, virtualized-system risks and protections. Secure a system by planning a baseline, installing trusted minimal software, configuring access, patching, restricting services, enabling logs/protection and backups, testing, and maintaining it. Automated patching speeds coverage and consistency but may cause compatibility problems, failed updates or reboots; use staged testing, maintenance windows, monitoring and recovery plans. Virtualization lets isolated guest systems share underlying hardware through a hypervisor. Risks include hypervisor compromise, guest escape, insecure management interfaces, VM sprawl, stale images, exposed virtual networking and sensitive snapshots.

Harden and patch hosts and guests, tightly restrict management access, segment virtual networks, protect images/snapshots, inventory VMs and verify backups. Isolation reduces risk but is not absolute. Project connection: a production detector should run in a hardened, maintained environment; a good ML score does not secure its host.

Cloud computing and IoT

The file named 9.1 is headed Assignment 9. It covers cloud computing, three service models, cloud threats, IoT and an IoT security framework. Cloud computing provides on-demand access to pooled, configurable computing resources. IaaS supplies infrastructure while customers manage OSs and applications; PaaS supplies a managed platform for customer applications; SaaS supplies an application service. Responsibilities vary by service and contract. Threats include misconfiguration, weak identity controls, exposed management APIs, data exposure, tenant-isolation failures and availability/dependency risks. IoT connects physical devices with sensing/actuation, software and network communication.

The brief names “the IoT security framework” without identifying a particular framework. Do not assume a single official diagram. A useful framework covers device identity and configuration, data protection, interface access control, secure software updates and cybersecurity state awareness across the lifecycle. TECH 3498 / ASSIGNMENT 9.2

Wireless network security

Assignment 9.2 asks whether a distribution system is wireless, the security areas and four phases of IEEE 802.11i, and benefits/weaknesses of open-system authentication. A distribution system connects access points and network segments; it need not be wireless and often uses wired infrastructure. 802.11i addresses authentication/access control, key management, and data confidentiality/integrity. A common four-phase summary is discovery, authentication, key generation/distribution, and protected data transfer; some detailed lifecycle descriptions add connection termination. Open-system authentication uses a simple request/response without proving possession of a secret. It is simple and interoperable but provides no meaningful identity authentication on its own; MAC addresses can be observed and spoofed.

A MAC allowlist is not a substitute for cryptographic authentication. Open-system exchange can precede a secure RSN association, so it does not by itself determine whether subsequent traffic is encrypted. For deployment, use supported modern Wi-Fi security, strong credentials, updates and segmentation rather than legacy weak modes. Project connection: Wi-Fi IoT devices need secure enrollment and link protection as well as traffic monitoring.
