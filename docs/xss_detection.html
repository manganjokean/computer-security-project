Assignment 6 — Cross-Site Scripting (XSS) Security and matching a research problem to an AI method.

Untrusted web input can carry XSS payloads; attackers obfuscate them to evade keyword filters. This project asks whether a character-level TextCNN trained with obfuscation augmentation detects obfuscated payloads more reliably than strong TF-IDF + Logistic Regression baselines — measured on a clean test set and on adversarially transformed hard sets.

Research question

Can a character-level TextCNN trained with obfuscation augmentation detect obfuscated XSS payloads more reliably than TF-IDF + Logistic Regression baselines, without sacrificing performance on clean input?

Objective: improve robustness (recall on obfuscated payloads) and false-positive safety (FPR on entity-encoded benign HTML), not just clean-set accuracy — clean-set scores are already saturated on this dataset.

Experimental design

  • Tuning on validation only: C for the baselines is chosen on validation F1; TextCNN uses early stopping on validation F1 (patience 3, max 12 epochs). The test split is touched once.
  • Hard sets from the held-out test split: every XSS test payload × 7 obfuscation transforms (mixed case, HTML entities, URL-encoding, NUL bytes, comment splitting, whitespace, multi-stage combined) = 7,693 obfuscated payloads, plus 530 entity-encoded benign snippets as a false-positive probe.
  • Metrics: Accuracy, Precision, Recall, F1, PR-AUC, FPR — not accuracy alone. Obfuscated detection = fraction of obfuscated XSS payloads still flagged.
  • Seed stability: E3/E4 repeated over seeds 42, 43, 44.
  • CPU-only: sequences padded/truncated to 300 characters, batch 64, Adam; the full suite runs in minutes.

Mitigation probe — NUL-byte input normalization

NUL-byte injection (on\x00error=) is a classic filter-evasion trick, so the probe strips NUL bytes from input before classification (inference only, no retraining):

Input handlingE2 Char TF-IDFE4 TextCNN + augment
raw0.99910.9982
NUL-stripped0.99910.9982

Detection was already ≈ 1.0 and stripping changes nothing: for these models the robustness comes from augmentation, not normalization. The probe also caught a pipeline bug worth documenting — an early version stored the hard sets as CSV, where pandas silently truncates strings at NUL bytes (ab\x00cd → ab), understating robustness by ~17 points. JSON storage fixed the measurement.

Limitations

  1. Clean-set scores are saturated (~0.999 for every serious model); this dataset separates easily, so meaningful differences appear only under obfuscation. Real request logs are noisier — replicate before operational conclusions.
  2. Trade-off: augmentation raises FPR on entity-encoded benign HTML (0.009 → 0.062 mean). An augmented model is more sensitive to entity-encoded content — exactly what escaped user text looks like. Deployment needs threshold tuning or encoding-aware validation, not one global threshold.
  3. Measurement integrity matters: the CSV/NUL truncation bug above shows a robustness claim is only as trustworthy as the pipeline measuring it.
  4. Single dataset with synthetic benign/attack provenance; obfuscation transforms approximate, but do not exhaust, real attacker evasion.
